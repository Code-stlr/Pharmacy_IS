# Pharmacy IS

A pharmacy management web application built with React, Django and PostgreSQL. Pharmacists manage patients, prescriptions and inventory; patients view their own records; administrators manage users and reference data.

This is a university MVP using fictional data. It is not intended for real clinical use.

## Features

- Neon Better Auth: verified email sign-up, email/password and Google sign-in, password recovery, logout and persistent sessions. Django retains Admin, Pharmacist and Patient roles.
- Multiple branch locations with independent inventory, shared patient records and cross-branch prescription fills.
- Configurable branch addresses and coordinates, with permission-based nearest-branch selection during signup and from the patient profile.
- Patient registration, profiles, prescriptions and dispensing history.
- Medication catalog, categories, suppliers, doctors and inventory batches.
- Prescription and OTC dispensing with validation and atomic stock updates.
- Search across patients, medications and prescriptions.
- Administrator-only user and reference-data management, with confirmed deletion and protected history.
- Responsive interface in English, Kazakh and Russian.

## Stack

React, TypeScript, Vite, Material UI and i18next on the frontend. Django REST Framework and PostgreSQL on the backend. Docker Compose runs PostgreSQL, Gunicorn/Django and an Nginx frontend proxy.

## Run locally

Install Docker Desktop with Linux containers and Docker Compose.

1. Copy `.env.example` to `.env`.
2. Set a unique `DJANGO_SECRET_KEY` and `POSTGRES_PASSWORD` in `.env`. Keep this file out of Git.
3. Start the application and wait for [localhost:8081](http://localhost:8081) to load.

```powershell
docker compose up --build -d --wait
```

4. Load the full fictional demo dataset and provision the shared team accounts.

```powershell
docker compose exec backend python manage.py seed_demo --full
docker compose exec backend python manage.py create_demo_users --shared-demo
```

5. Open [localhost:8081](http://localhost:8081). Sign in with `Demo-Pharmacy-2026!` as `admin_demo` (Admin), `pharmacist_demo` (Pharmacist), or `patient_demo` (Patient).

The shared login is public and intended for fictional data on localhost. Existing accounts keep their passwords when provisioning is rerun. For a custom demo password on a fresh database, pass `DEMO_PASSWORD` to `create_demo_users` and omit `--shared-demo`.

On a fresh database, `seed_demo --full` generates 104 fictional patients, 102 dispensing events, 27 medications, 106 stock batches, and five allergy catalog entries. It uses synthetic data generated by the source code. Omit `--full` for the small acceptance-test seed. Re-running the seed preserves existing records, stock, and passwords. Migrations run on startup and PostgreSQL data persists in a Docker volume. API readiness is available at `/api/health/`, and authenticated API documentation is at `/api/docs/`.

This configuration is for local use. Public hosting still needs TLS, production settings, secret management and verified backups.

## Tests

For the complete isolated verification, install Node 24 and the browser dependencies, then run:

```powershell
cd frontend
npm ci
npx playwright install chromium
cd ..
$env:DEMO_PASSWORD='replace-with-your-demo-password'
./scripts/verify.ps1
```

The script builds a separate acceptance stack on port 8181 and runs backend, frontend, schema and browser checks without resetting the main database. Use the acceptance accounts' existing password on later runs. See the [application guide](docs/application.md) for individual test commands and development setup.

## Neon database and authentication

The local `.env` selects the migrated Neon database and managed Better Auth. Configuration and the verified migration record are documented in [Neon setup](docs/neon-auth.md). Existing pharmacy accounts link to a verified Neon identity using their old username/password; this preserves their role and records. New sign-ups receive Patient access only.

The [public demo staff accounts](DEMO_ACCOUNTS.md) provide one administrator and two pharmacists per branch with direct login IDs. They are already assigned roles/branches and do not require personal email or account linking. Staff can change their password from **My profile** without email.

Neon sends verification and reset codes through its shared development email provider. Google uses shared development keys until your own OAuth app is configured. Keep credentials in `.env`, never in source. The original local database and pre-migration backups remain available privately.
